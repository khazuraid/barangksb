# Migrasi InventarisKantor ke Golang (Full-stack Go Murni)

**For Hermes:** Gunakan subagent-driven-development skill untuk implementasi task-by-task. **Goal:** Rewrite total aplikasi inventaris kantor (barcode + stok real-time) dari React/Firestore menjadi full-stack Go: satu binary, server-rendered templ, PostgreSQL, session auth sendiri — Firebase dihapus total.

**Architecture:** Go server (`net/http` + chi) render HTML via `templ`. Semua state di PostgreSQL. Real-time stok via SSE (Server-Sent Events) stdlib, pengganti `onSnapshot`. Auth Google/Firebase diganti session cookie + bcrypt + role. Foto upload ke Google Drive. UI hasil render server + sedikit vanilla JS (kamera scan, geotag, audio).

**Tech Stack:** Go 1.23+, chi, templ, PostgreSQL (pgx/v5), sqlc, scs (session), goose (migrasi), boombuler/barcode + skip2/go-qrcode, go-pdf/fpdf, google.golang.org/api/drive/v3.

## Risiko & Tradeoff
- **Postgres dependency:** butuh server Postgres (lokal: docker postgres:16; deploy: Coolify/Zeabur sudah terbiasa). Volume DB wajib di-preserve — sama aturan dengan sistem kesling.
- **SSE vs WebSocket:** SSE cukup (one-way). Full reload sederhana dulu.
- **EAN13 checksum** bisa menolak SKU lama yang tidak standar — default CODE128, EAN13 opt-in.
- **Firestore data lama:** tidak ada — keputusan final, tidak perlu tool import.
- **@google/genai & GEMINI_API_KEY:** tidak dipakai di kode lama (0 referensi) — tidak diporting.
